# BossPDF

PDF 뷰어 겸 편집기. 2.0부터 러스트로 다시 만들었습니다(1.x는 파이썬 + PySide6).
엔진은 MuPDF, 화면은 Slint입니다.

## 들어 있는 기능
- PDF 열기 (Ctrl+O, 명령줄 인자, 암호 문서)
- 연속 스크롤 (보이는 페이지만 렌더링)
- 확대/축소 (Ctrl+휠, Ctrl+`+`/`-`), 너비 맞춤 (Ctrl+0)
- 썸네일 사이드바 (Ctrl+B)
- 문서 내 검색 (Ctrl+F, Enter/F3 다음, Shift+F3 이전). 스캔본처럼 글자 층이 없는 쪽은 윈도우 내장 글자 인식(OCR)으로 찾음
  - 텍스트 검색 결과를 먼저 보여 주고, 그림이 든 쪽·글자가 거의 없는 쪽만 이어서 인식(검색 막대에 "글자 인식 n / 전체" 표시)
  - 한글 자모가 비슷하게 잘못 읽힌 경우(한 글자까지)도 찾음. 인식 결과는 문서를 편집하기 전까지 기억
- 페이지 번호 입력으로 이동
- 편집: 텍스트 추가(클릭 후 입력), 텍스트 수정(기존 글자를 드래그하면 내용·크기·색을 읽어 와 고쳐 씀),
  가리기·형광펜(드래그), 손글씨/서명(그리기)
- 텍스트 서식 막대: 설치된 글꼴 선택, 크기(6~72pt), 굵게, 색 5가지
- 페이지 조작: 썸네일 우클릭 메뉴(90° 회전, 앞/뒤/맨 앞/맨 뒤로 이동, 삭제), 썸네일을 위아래로 끌어 순서 바꾸기
- 내보내기 (Ctrl+E): 고른 쪽을 새 PDF, 쪽별 이미지(PNG/JPG), 이어 붙인 긴 이미지로. 쪽 범위는 `1-3, 5, 8-` 형식, 해상도 100/150/300 DPI
- 합치기: PDF와 이미지(PNG·JPG·BMP·GIF·TIFF·WebP)를 섞어 목록 순서대로 하나의 PDF로. 이미지는 A4 맞춤(여백 4단계) 또는 원본 크기.
  합친 뒤 결과를 바로 엽니다. 명령줄 `BossPDF.exe --merge 파일1 파일2 …`로 목록을 채운 채 시작할 수 있습니다.
- 인쇄 (Ctrl+P): 윈도우 인쇄 대화상자에서 프린터·쪽 범위·부수를 고름. 각 쪽을 용지 인쇄 영역에 비율을 지켜 가운데에 놓고,
  쪽과 용지의 방향이 다르면 90° 돌려서 찍음. 최대 300dpi로 그려 보냄
- 자동 업데이트: 시작할 때 GitHub 릴리스(cirross2/Bosspdf)를 확인해 새 버전이 있으면 알리고, 설치 파일을 받아 실행.
  왼쪽 레일 맨 위 ☰ 단추의 정보 창에서 직접 확인할 수도 있음
- 암호 없이 저장: 암호 문서를 열었을 때 정보 창에서 암호를 푼 사본을 저장
- 탐색기 연동 (설치 프로그램이 등록. 설치 없이 쓸 때는 `BossPDF.exe --register` / `--unregister`)
  - PDF: "BossPDF로 PDF 합치기" / 이미지: "BossPDF로 PDF 병합" — 키 이름과 글자는 1.x와 같아서 그대로 이어집니다.
  - 1.x의 우클릭 메뉴가 넘기던 `--merge-pdfs`, `--merge-images`, `--new-process` 인자도 받습니다.
  - 여러 파일을 골라 합치기를 누르면 창 하나에 모입니다(이름순 정렬, 늦게 도착한 파일도 추가).
  - 이미 열려 있는 문서를 또 열면 새 창 대신 그 창을 앞으로 가져옵니다. 다른 문서는 새 창(새 프로세스)으로 엽니다.
- 다크/화이트 테마 전환 (Ctrl+T, 왼쪽 레일 맨 아래 단추). 색은 파이썬 버전의 팔레트와 같음
- 설정 기억: 테마, 썸네일 사이드바 표시, 창 크기·위치·최대화 (`%APPDATA%\BossPDF\settings.ini`)
- 실행 취소 (Ctrl+Z, 10단계), 저장 (Ctrl+S), 다른 이름으로 저장 (Ctrl+Shift+S)
- 저장하지 않은 변경이 있으면 창을 닫거나 다른 문서를 열 때 확인

편집은 파이썬 버전과 같은 방식(페이지 내용에 직접 그리기)이고, 저장은 임시 파일에 쓴 뒤 교체합니다.
텍스트 수정은 드래그한 영역을 흰색으로 덮고 원래 첫 글자의 밑선 위치에 새 글을 씁니다(한 번의 실행 취소로 되돌림).
입력창에서 Enter는 적용, Shift+Enter는 줄바꿈, Esc는 취소입니다.

아직 없는 것: 기울임·정렬·임의 색 선택, 클릭 위치 줄맞춤(스냅), 인쇄 미리보기,
파일을 창에 끌어다 놓기, 마지막으로 쓴 폴더 기억, 한 프로세스 안의 여러 창(문서마다 프로세스를 따로 띄움).

알려진 한계
- 텍스트를 넣은 문서는 저장할 때 글꼴을 실제로 쓴 글자만 남기도록 줄입니다(MuPDF `pdf_subset_fonts`).
  이때 문서에 원래 들어 있던 글꼴도 함께 줄어듭니다. 화면 표시는 그대로지만, 그 글꼴로 새 글자를 쓰는 다른 편집기에서는
  글자가 모자랄 수 있습니다. 입력 양식(AcroForm)이 있는 문서는 그래서 줄이지 않고, 글꼴 전체(수 MB)가 들어갑니다.
- 글자 인식은 쪽당 0.3초쯤 걸립니다. 쪽마다 로고 같은 그림이 있는 긴 문서는 인식 단계가 오래 걸릴 수 있습니다
  (텍스트 결과는 바로 나오고, 인식은 뒤에서 이어집니다). 윈도우에 한국어 OCR 언어 팩이 없으면 이 단계는 건너뜁니다.
- 인쇄는 쪽을 그림으로 그려 보냅니다(파이썬 버전과 같은 방식). 인쇄 도중 취소 버튼은 없습니다.
  파이썬 버전은 대화상자의 쪽 범위를 무시하고 전체를 용지에 늘려 찍었는데, 여기서는 쪽 범위·부수를 따르고 비율을 지킵니다.
- 암호가 걸린 PDF는 합칠 수 없습니다(먼저 열어서 암호 없이 저장해야 함). 파이썬 버전은 합칠 때 비밀번호를 물어봅니다.
- 합치기 목록은 버튼으로만 순서를 바꿉니다(끌어서 바꾸기·파일 끌어다 놓기 없음). 이어 붙인 이미지는 2억 5천만 픽셀까지만 만듭니다.
- 굵은 글꼴 파일이 따로 없는 글꼴은 굵게를 골라도 보통 굵기로 들어갑니다.
- 텍스트 수정은 원래 글자를 지우지 않고 덮습니다(파이썬 버전과 동일). 검색하면 덮인 글자도 여전히 찾아집니다.
- 실행 취소는 편집마다 문서 전체 사본을 메모리에 보관합니다(파이썬 버전과 동일). 큰 문서에서는 느려질 수 있습니다.
- 회전한 페이지에서 형광펜은 보이는 위치에 맞게 들어가는 것을 확인했습니다. 회전한 페이지에 넣는 텍스트의 방향은 확인하지 않았습니다.
- 썸네일을 끄는 동안 목록이 자동으로 스크롤되지 않습니다. 멀리 옮길 때는 우클릭 메뉴의 "맨 앞으로/맨 뒤로"를 쓰세요.
- 페이지 조작이나 실행 취소 뒤에는 그려 둔 화면을 모두 버리고 다시 그립니다(잠깐 흰 쪽이 보일 수 있음).

## 구성
- `src/engine.rs` — MuPDF 문서를 소유하는 작업 스레드 (렌더링·검색·썸네일)
- `src/main.rs` — 배치 계산, 스크롤 가상화, 화면과 엔진 연결
- `src/output.rs` — 내보내기와 합치기
- `src/print.rs` — 인쇄 (윈도우 GDI)
- `src/ocr.rs` — 스캔 쪽 검색용 글자 인식 (Windows.Media.Ocr)
- `src/settings.rs` — 설정 저장·불러오기
- `src/updater.rs` — 자동 업데이트 (GitHub 릴리스 확인·내려받기)
- `src/shell.rs` — 탐색기 연동 (우클릭 메뉴 등록, 합치기 파일 모으기, 같은 문서 창 찾기)
- `src/fonts.rs` — 글꼴 찾기(문서 표시용, 텍스트 편집용 목록)
- `src/selftest.rs` — 개발용 자동 점검 (`--selftest`)
- `ui/app.slint` — 화면 정의 (Slint)
- `installer/BossPDF_Setup.iss` — 설치 프로그램 정의 (Inno Setup)

## 빌드
러스트 도구는 `E:\다운로드\rust`에 있고 시스템 PATH에는 등록하지 않았습니다.

```powershell
. .\env.ps1
cargo fetch
.\scripts\vendor-mupdf.ps1   # 처음 한 번: MuPDF 래퍼 수정본 준비
cargo build --release
```

결과물: `target\release\BossPDF.exe` (단독 실행 파일)

배포용 설치 파일은 `scripts\build-release.ps1`로 만듭니다(빌드 → 서명 → Inno Setup → `dist\BossPDF_Setup_v<버전>.exe`).
버전은 `Cargo.toml`의 `version` 한 곳만 올리면 됩니다. 설치 파일은 1.x와 같은 AppId·설치 위치를 써서,
기존 설치본 위에 설치하면 파이썬 실행 환경 폴더(`_internal`)를 지우고 2.x로 바꿉니다.
`-Test`를 붙이면 레지스트리와 바로가기를 건드리지 않는 시험용 설치 파일이 나옵니다.

`vendor\mupdf-sys`, `vendor\mupdf`는 원본 패키지에 다음을 고친 사본입니다(스크립트가 만듦, git에는 넣지 않음).
- 이 PC의 컴파일러(MSVC 17.4)에서 안 읽히는 C 구문 5곳과 `max_align_t` 정의
- 글꼴 부분 포함 함수 `PdfDocument::subset_fonts` 추가

## 자동 점검
```powershell
target\release\BossPDF.exe 문서.pdf --selftest 결과폴더 --search 검색어
```
열기 → 가운데 페이지 이동 → 검색 → 확대 → 편집(마우스·키보드 이벤트를 창에 직접 넣음) → 실행 취소 → 저장을 수행하고,
단계별 화면(PNG)과 `report.txt`를 남긴 뒤 종료합니다. 원본은 건드리지 않고 `결과폴더\edited.pdf`로 저장합니다.
환경 변수 `BOSSPDF_SAVE_INPLACE=1`이면 연 파일에 덮어쓰기 저장을 시험하므로 반드시 사본으로 실행하세요.

## 측정 결과 (2026-11-16, 240쪽 시험 문서, 이 PC 기준)
| 항목 | 파이썬 v1.0.6 | 러스트 시제품 |
|---|---|---|
| 배포 크기 | 폴더 114MB / 설치 파일 37MB | exe 하나 18MB (압축 시 10MB) |
| 시작 | 창 표시까지 약 2.1초 | 첫 페이지 표시까지 약 1.2초 |
| 메모리(작업 집합) | 약 238MB | 약 146MB |

- 측정 방식이 다릅니다: 파이썬은 창 핸들이 생기는 시점, 러스트는 내부 기록(`--selftest`의 "시작 과정")입니다.
- 러스트 시작 시간 1.2초 중 약 0.75초는 창 생성(Slint가 시스템 글꼴을 읽는 구간으로 추정), 약 0.35초는 GPU 첫 프레임입니다.
- 소프트웨어 렌더러(`SLINT_BACKEND=winit-software`)는 시작이 약 0.65초로 더 빠르지만, 3400x1380 창에서 한 프레임에 약 50ms가 걸려 스크롤이 끊깁니다. 그래서 기본은 GPU입니다.
- 기능 범위가 다릅니다. 시제품에는 편집·인쇄·OCR·업데이트가 없으므로, 기능을 옮기면 크기는 늘어납니다.

## 1.x (파이썬 버전)
1.0.6까지의 파이썬 + PySide6 소스는 `legacy-python/` 폴더에 그대로 남겨 두었습니다. 더는 배포하지 않습니다.
